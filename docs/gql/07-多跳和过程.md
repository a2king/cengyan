# 多跳和过程

变长跳写在箭头后面，必须写出上界。默认最多 10 跳，由 `max_hops` 决定。

## 变长 MATCH

```text
MATCH (a:Company {id:1})-[:holder]->{3}(b) RETURN b.id
MATCH (a:Company {id:1})-[:holder]->{1,3}(b) RETURN b.id
MATCH (a {id:1})-[:holder|:works]->{1,2}(b) RETURN b.id
MATCH (a {id:1})-[e]->{1,2}(b) RETURN b.id
```

- `{3}`：正好第 3 跳新到达的点。
- `{1,3}`：第 1 跳到第 3 跳新到达的点，合在一起。
- 一个点一旦到达过，后面的跳不再进入它。所以这不是「所有路径」，同一个终点只出现一次。
- 类型可以是一个、多个（`|`），或者不写。

`*` 会报「不支持所有路径，请用最短路或给跳数加上边界」：

```text
MATCH (a:Company {id:1})-[:holder]->*(b) RETURN b.id
```

每一跳的新点数量默认不能超过 64（`max_frontier_per_hop`）。超过报 `FRONTIER_EXCEEDED`。每个起点检查的边同样受每点上限约束，超过报 `TRUNCATED`。

多跳的 `WHERE` 目前只能比较边的 `rank` 和终点的 `id`。比较 `e.ratio`、`RETURN e` 都会报「多跳查询的条件目前只能比较 rank 和终点 id」。

多跳会先在上限之内扩完，再做 `ORDER BY`、`DISTINCT`、`SKIP`、`LIMIT`。

## 最短路

```text
CALL path.shortest({start: 1, end: 2, rel: "holder", hops: 10}) YIELD length, vids
```

参数都要写。`start`、`end` 是点的编号，`rel` 是一个边类型名，`hops` 是最多几跳。`YIELD` 只能是 `length`、`vids`，两个都可以省略其中一个，不能多写。

找不到路时没有行。`vids` 是从起点排到终点的编号列表，`length` 是边数。路沿着这一种边的出方向走：从 `start` 出发能顺着箭头到达 `end`。

## 有界子图

```text
CALL subgraph.bounded({start: 1, rel: "holder", hops: 3}) YIELD vid
```

从起点沿这种边的出边和入边一起扩，最多 `hops` 跳。结果包含起点。`hops: 0` 只有起点。`YIELD` 只有 `vid`。

## 穿透持股

```text
CALL ownership.largest_holder({start: 1, rel: "holder", ratioProp: "ratio", hops: 10}) YIELD vid, ratio
```

沿出边走。边的比例属性由 `ratioProp` 指定，这个属性必须是 `DOUBLE`。单条比例低于 `min_edge_ratio`（默认 `0.01`），或一路乘下来低于 `min_accum_ratio`（默认 `0.001`），就不再往下走。环不会把同一段比例再乘一次。

`YIELD` 是 `vid` 和 `ratio`。没有符合条件的下游点时没有行。

## 标准里还有

标准把最短路写在 `MATCH` 里，并区分「任意一条最短」「全部最短」「前 k 条」，还可以规定路径能不能重复点、重复边。这里只有上面这一个过程，返回一条路。

无上界变长、所有路径、在多跳结果里读取边的属性，都还没有。

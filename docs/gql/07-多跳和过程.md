# 多跳和过程

变长跳写在箭头后面，必须写出上界。执行预算 `max_hops` 默认是 `0`（不限）；部署者可以配置正数保护实例。语法本身仍要求写出路径范围。

## 变长 MATCH

```text
MATCH (a:Company {id:1})-[:holder]->{3}(b) RETURN b.id
MATCH (a:Company {id:1})-[:holder]->{1,3}(b) RETURN b.id
MATCH (a {id:1})-[:holder|:works]->{1,2}(b) RETURN b.id
MATCH (a {id:1})-[e]->{1,2}(b) RETURN b.id
```

- `{3}`：正好第 3 跳新到达的点。
- `{1,3}`：第 1 跳到第 3 跳新到达的点，合在一起。
- `RETURN b` 带上这个点实际类型的属性。`(b)` 没写类型时，按点上已有的类型去读，所以同一次结果里可以既有 `org` 也有 `person`。
- 一个点一旦到达过，后面的跳不再进入它。所以这不是「所有路径」，同一个终点只出现一次。
- 类型可以是一个、多个（`|`），或者不写。

`*`、`+` 和 `{2,}` 可以写。`max_hops` 配置成 0（不限）时，没写出上界会报「请写上界或配置 max_hops」。路径上的 `LIMIT` 是截断，不再因为超过条数失败；超过 `max_paths` 预算仍会报错。

路径模式前缀：

| 写法 | 语义 |
|---|---|
| `WALK` | 节点和边都允许重复；不写模式前缀时默认按 `WALK` 执行 |
| `TRAIL` | 同一条路径中的边不能重复，节点可以重复 |
| `SIMPLE` | 中间节点不能重复，但允许最后一条边回到起点形成闭环；闭环后不再继续扩展 |
| `ACYCLIC` | 路径上任何节点都不能重复，真正无环 |

示例：

```text
MATCH p = WALK (a {id:1})-[:inv]->{1,3}(b) RETURN p LIMIT 50
MATCH p = TRAIL (a {id:1})-[:inv]-{1,3}(b) RETURN p LIMIT 50
MATCH p = SIMPLE (a {id:1})-[:inv]-{1,3}(b) RETURN p LIMIT 50
MATCH p = ACYCLIC (a {id:1})-[:inv]-{1,3}(b) RETURN p LIMIT 50
```

`SIMPLE` 只允许回到当前路径的起点；回到中间节点仍会被丢弃。所有模式都受 `max_paths`、`max_frontier_per_hop` 和 `max_edges_per_vertex` 限制。

```text
MATCH (a:Company {id:1})-[:holder]->*(b) RETURN b.id
MATCH (a:Company {id:1})-[e:inv]->{1,3}(b) WHERE e.ratio > 0.1 RETURN b.id
```

每一跳的新点数量是否受限由 `max_frontier_per_hop` 决定，默认 `0`（不限）。配置正数后超过预算报 `FRONTIER_EXCEEDED`。每个起点检查的边同样受 `max_edges_per_vertex` 预算约束，超过报 `TRUNCATED`。

多跳可以比较边属性。只比较 `rank` 和终点 `id` 时仍走原来的到达点扫描；写了别的边属性时按路径展开后再过滤。

多跳会先在上限之内扩完，再做 `ORDER BY`、`DISTINCT`、`SKIP`、`LIMIT`。

## 路径搜索前缀

当前支持最短路径前缀：

```text
MATCH p = ANY SHORTEST
    (s {id:'A'})-[:inv]-{1,6}(t {id:'B'})
RETURN p

MATCH p = ALL SHORTEST TRAIL
    (s {id:'A'})-[:inv]-{1,6}(t {id:'B'})
RETURN p
LIMIT 50
```

`ANY SHORTEST` 返回一条到达目标的最短路径；`ALL SHORTEST` 返回同一最短深度的路径。目标节点写了 `{id:...}` 时，BFS 只有真正到达该目标才会产生结果，不会把第一层中间节点误当作终点。

起点和终点都可以使用 ID 集合：

```text
MATCH p = ALL SHORTEST TRAIL
    (s)-[:inv]-{1,5}(t)
WHERE s.id IN ['A', 'B']
  AND t.id IN ['X', 'Y', 'Z']
RETURN p
LIMIT 50
```

起点集合和终点集合都会在路径搜索前解析为候选 ID。无向 `-[:inv]-` 使用存储中的入边和出边键。

当前 `ALL/ANY SHORTEST TRAIL` 使用分层 BFS 和节点访问去重，业务效果是无环最短路径；如果要求允许重复节点但同一条边不能重复的完整 TRAIL 语义，需要继续使用独立路径状态执行器。

## 路径计算与分组

路径可以先用 `LET` 计算逐路径指标，再按终点聚合：

```text
MATCH p =
    (start:org)-[:inv]->{1,6}(shareholder:person)
WHERE id(start) = 'q企业eid'

LET path_conprop =
    REDUCE(acc = 1.0, rel IN relationships(p) |
           acc * coalesce(rel.conprop, 0.0))

RETURN
    id(shareholder) AS end_node,
    collect_list(nodes(p)) AS node_list,
    collect_list(relationships(p)) AS path_list,
    sum(path_conprop) AS total_conprop
GROUP BY shareholder
FILTER total_conprop >= 0.25
ORDER BY total_conprop DESC
LIMIT 10000
```

`WHERE id(start)=...` 会下推为起点点查；`id(start) IN [...]` 可以一次给出多个起点。`FILTER` 在 `GROUP BY` 和聚合之后执行。

## 最短路

```text
CALL path.shortest({start: 1, end: 2, rel: "holder", hops: 10}) YIELD length, vids
```

参数都要写。`start`、`end` 是点的编号，`rel` 是一个边类型名，`hops` 是最多几跳。`YIELD` 只能是 `length`、`vids`，两个都可以省略其中一个，不能多写。

找不到路时没有行。`vids` 是从起点排到终点的编号列表，`length` 是边数。路沿着这一种边的出方向走：从 `start` 出发能顺着箭头到达 `end`。

## 全部路径

不写路径变量时，`{3}` 仍然只返回每个点第一次到达的终点。要整条路，把路径变量绑在 `MATCH` 上，用 `RETURN` 把 `p` 取出来。一条路上的点不重复。下一条边如果回到当前这条路上，就丢掉这条边，不再往下走。已经走完且跳数落在范围内的前缀仍然返回。

```text
MATCH p = (a:org {id:"q2f8c0cfe092811ed853000163e0ee983"})-[:inv]->{1,3}(b) RETURN p LIMIT 10000
MATCH p = (a {id:"A"})-[:inv]->{1,3}(b {id:"B"}) RETURN p LIMIT 10000
MATCH p = (a {id:"A"})-[]->{1,3}(b) RETURN p LIMIT 10000
MATCH p = (a {id:"A"})<-[:inv]-{1,3}(b) RETURN p LIMIT 10000
```

起点必须写 `id`。`{3}` 是正好 3 跳，`{1,3}` 是 1 到 3 跳。终点写在 `(b {id:"B"})` 上时，只返回正好停在这个点上的路，到达终点后这条路不再往下走。不写终点时，范围内的每一条前缀都是一行。方向是 `->` 出、`<-` 入、`--` 双向。边类型可以省略，也可以写成 `[:inv|:holder]`。

`LIMIT` 必须写。它是允许返回的最多条数，再多一条就报 `PATH_LIMIT_EXCEEDED`，不截断后当作成功。绕回起点的闭环不会接回起点，所以从一点到它自己没有行。

`RETURN p` 的每一行是一个对象：

```json
{
  "length": 2,
  "nodes": [
    {"id": "e_001", "type": "org", "properties": {"entname": "甲公司"}},
    {"id": "e_002", "type": "org", "properties": {"entname": "乙公司"}},
    {"id": "e_004", "type": "person", "properties": {"name": "张三"}}
  ],
  "edges": [
    {"type": "inv", "rank": 0, "src": "e_001", "dst": "e_002", "properties": {"ratio": 0.5, "since": null}},
    {"type": "inv", "rank": 0, "src": "e_002", "dst": "e_004", "properties": {"ratio": 0.2, "since": null}}
  ]
}
```

`edges` 的条数等于 `length`，也等于 `nodes` 条数减 1。第 `i` 跳从 `nodes[i]` 走到 `nodes[i+1]`。`src` 和 `dst` 是边入库时的方向：顺着出边走时 `src` 等于 `nodes[i]`，逆着入边走时两者对调。点和边都带上各自类型里定义的属性，没写入的字段是 `null`。边类型没有字段时，`properties` 是空对象。

同一条结果也可以用过程取。`YIELD` 是 `length` 和 `path`，`path` 就是上面这个对象。

```text
CALL path.all({start: "q2f8c0cfe092811ed853000163e0ee983", rel: "inv", min: 1, max: 3, direction: "out", limit: 10000}) YIELD length, path
CALL path.all({start: "A", end: "B", rel: "inv", min: 1, max: 3, limit: 10000}) YIELD path
```

`max` 和 `limit` 必须写。`min` 省略时是 1。`direction` 省略时是 `out`，还可以写 `in` 或 `both`。`rel` 省略时不限边类型，多种类型写成 `"inv|holder"`。不写 `end` 时返回范围内的每一条路。写了 `end` 时只返回停在终点上的路。

## 有界子图

```text
CALL subgraph.bounded({start: 1, rel: "holder", hops: 3}) YIELD vid
```

从起点沿这种边的出边和入边一起扩，最多 `hops` 跳。结果包含起点。`hops: 0` 只有起点。`YIELD` 只有 `vid`。

## 穿透持股

```text
CALL ownership.largest_holder({start: 1, rel: "holder", ratioProp: "ratio", hops: 10}) YIELD vid, ratio
```

沿出边走。边的比例属性由 `ratioProp` 指定，这个属性必须是 `DOUBLE`。单条比例低于 `min_edge_ratio`（默认 `0.01`），或一路乘下来低于 `min_accum_ratio`（默认 `0.001`），就不再往下走。环不会把同一段比例再乘一次。

`YIELD` 是 `vid` 和 `ratio`。没有符合条件的下游点时没有行。

## 标准里还有

标准把最短路写在 `MATCH` 里，并区分「任意一条最短」「全部最短」「前 k 条」，还可以规定路径能不能重复点、重复边。当前服务端同时保留 `CALL path.shortest(...)` 扩展过程：它适合单起点、单终点、单边类型，返回 `length` 和 `vids`；需要完整节点/边属性时使用 `MATCH p = ... RETURN p`。

无上界变长还没有。全部简单路径用上面的 `MATCH p = ... RETURN p`。

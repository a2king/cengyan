# 插入

`INSERT` 写点和边。点的编号写在花括号里的 `id`。带类型名时，这个点会按该类型写入；只有 `({id:1})` 时不创建点，只在边上使用这个编号。

## 只插入点

```text
INSERT (a:Company {id:1, name:'root'})
INSERT (a:Company {id:2, name:'sub', capital: 100})
```

必填列都要给值。可空列可以不写。多写一个类型里没有的属性，会报未知属性。`id` 必须是整数。

同一个 `id` 再插入一次，后写的属性盖住同名列。类型必须和原来的点一致。

## 插入一条边

```text
INSERT (a:Company {id:1, name:'root'})-[:holder {ratio:0.5}]->(b:Company {id:2, name:'sub'})
INSERT (a {id:1})-[:holder {ratio:0.2}]->(b {id:3})
INSERT (a {id:3})<-[:holder {ratio:0.1}]-(b {id:1})
```

箭头是边的逻辑方向。

- `(a)-[:holder]->(b)`：a 是出端，b 是入端。
- `(a)<-[:holder]-(b)`：b 是出端，a 是入端。

插入必须有方向，必须正好一个类型名。下面两种都会报「插入边必须写一个类型」：

```text
INSERT (a {id:1})-[e]->(b {id:2})
INSERT (a {id:1})-[:holder|:works]->(b {id:2})
```

无方向的 `-[e:holder]-` 会报「插入边必须有方向」。箭头后面再写 `{1,3}` 会报「插入边不能是多跳」。

## rank

同一对点、同一个类型、同一个方向上，用 `@` 后面的整数区分多条边。不写就是 `0`。

```text
INSERT (a {id:1})-[:holder@3 {ratio:0.1}]->(b {id:2})
```

再插入相同的类型、`rank`、出端、入端，这条边会被盖住。

## 读回来

```text
MATCH (a:Company {id:1}) RETURN a
MATCH (a {id:1})-[e:holder]->(b) RETURN e
```

点的形状：

```json
{"id":1,"type":"Company","properties":{"name":"root"}}
```

边的形状：

```json
{"type":"holder","rank":0,"src":1,"dst":2,"properties":{"ratio":0.5}}
```

`src`、`dst` 是逻辑出端和入端，不跟着查询时的箭头对调。

## 标准里还有

标准的 `INSERT` 可以在一条语句里写更完整的图模式，包括多段边。这里一条 `INSERT` 要么是一个点，要么是一条边。没有 `MERGE`。

# 标准 GQL 与层岩扩展边界

本项目把语法分成三层：

## 标准 GQL

标准 GQL 是兼容性目标。已经实现的标准子集包括点模式、单边模式、有界量化路径、`WHERE`、`RETURN`、`DISTINCT`、`ORDER BY`、`SKIP`、`LIMIT`、参数、三值逻辑、算术、比较、`INSERT`、`SET` 和 `DELETE`。有界量化在不绑定路径变量时返回新到达的点；写成 `MATCH p = ... RETURN p LIMIT n` 时返回全部简单路径。

尚未覆盖的标准语法标记为 planned，不伪装成层岩语法。

## 层岩扩展

下面的能力属于产品扩展：

```text
CREATE GRAPH
USE
CREATE NODE TYPE
CREATE REL TYPE
CREATE INDEX
SHOW / DESCRIBE
CALL path.shortest(...)
CALL path.all(...)
CALL subgraph.bounded(...)
CALL ownership.largest_holder(...)
COMMENT '...'
bulkInsert JSON 协议
EXPLAIN
```

扩展语法必须在文档中明确标注为层岩扩展，不改变标准 GQL 已实现语法的含义。对于 `COMMENT` 这类 Schema 元数据扩展，关键字直接附着在对应的 DDL 定义上。

## 执行策略

超时、内存、扫描边数、前沿大小、最大跳数和最大路径数不是 GQL 语义，而是执行策略。预算值为 `0` 表示不限；默认不限制边数、前沿、跳数和路径数。受限部署可以通过 `cengyan.properties` 重新设置预算。

```properties
max_edges_per_vertex=10000
max_frontier_per_hop=100000
max_hops=1000
max_paths=100000
max_execution_time_ms=60000
```

## Schema 注释与批量导入

`COMMENT '...'` 是层岩 Schema 扩展，可用于图空间、点类型、边类型和字段。注释会持久化到 Catalog，并通过 `SHOW GRAPHS`、`SHOW NODE TYPES`、`SHOW REL TYPES` 和 `DESCRIBE` 的 `comment` 列返回。

`bulkInsert` 是服务端 JSON 导入协议，不是 GQL 文本语法。它将一批节点或边组装为一次 RocksDB `WriteBatch`，用于大规模导入。

`EXPLAIN` 是只读诊断扩展，沿用 `execute` 协议，不需要新的网络操作类型。

# 标准 GQL 与层岩扩展边界

本项目把语法分成三层：标准 GQL、层岩扩展、执行策略。扩展不改变标准写法的含义；同一段文字在标准里合法时，按标准的意思执行。

## 标准 GQL

兼容性目标，已支持的部分见 [和标准相比](00-和标准相比.md)。和旧版本相比，下面这些按标准改过含义，详见 [本轮标准对齐变更](13-本轮标准对齐变更.md)：

- `--` 是行注释。
- 属性默认可空，`NOT NULL` 才必填。
- `OR` 和 `XOR` 同一优先级。
- `USE g 查询` 只对这一条查询换图。

## 层岩扩展

```text
CREATE GRAPH ... PARTS n REPLICAS n ID INT64|STRING(n) COMMENT '...'
CREATE / DROP ALIAS
CREATE NODE TYPE / CREATE REL TYPE / DROP NODE|REL TYPE / ALTER ... ADD|DROP|RENAME
CREATE [UNIQUE] INDEX / DROP INDEX
SHOW / DESCRIBE / EXPLAIN
COMMENT '...'
边的 rank：-[:holder@3]->
点模式里的 {id: ...} 和 n.id
x IN [..]、x IN (a, b)、x IN $list（标准没有列表成员谓词）
标签里的关键字 AND（等于 &）
RETURN ... FILTER 条件（分组后过滤，相当于 HAVING），以及整条查询后的 FILTER
REDUCE(acc = 初值, x IN 列表 | 表达式)
starts_with / ends_with / contains / regex_match / labels / type / properties / nodes / relationships / startNode / endNode / id
单参数 LOG(x)（等于 LN）、TRIM(s, 字符)
CALL ns.proc({名字: 值}) 和过程 path.shortest / path.all / subgraph.bounded / ownership.largest_holder
bulkInsert JSON 协议
```

扩展语法必须在文档中明确标注为层岩扩展。

## 执行策略

超时、内存、扫描边数、前沿大小、最大跳数和最大路径数不是 GQL 语义，而是执行策略。当前部署使用 Storage/Compute 角色配置，Compute 的请求时间、内存、临时磁盘和结果额度必须满足角色配置校验。

```properties
max_edges_per_vertex=10000
max_frontier_per_hop=100000
max_hops=1000
max_paths=100000
max_execution_time_ms=60000
```

路径枚举另有硬上限：跳数上界不超过 32、路径数不超过 100000。

## Schema 注释与批量导入

`COMMENT '...'` 是层岩 Schema 扩展，可用于图空间、点类型、边类型和字段。注释会持久化到 Catalog，并通过 `SHOW GRAPHS`、`SHOW NODE TYPES`、`SHOW REL TYPES` 和 `DESCRIBE` 的 `comment` 列返回。

`bulkInsert` 是服务端 JSON 导入协议，不是 GQL 文本语法。

`EXPLAIN` 是只读诊断扩展，沿用 `execute` 协议。

# 名字和字面量

关键字不区分大小写。图名、类型名、属性名、变量名区分大小写。`MATCH` 和 `match` 相同，`Company` 和 `company` 是两个名字。

## 名字

名字由英文字母开头，后面可以是英文字母、数字、下划线。不能用中文，不能以数字或下划线开头，最长 128 字节。

`id` 可以做变量名，也可以写在点的模式里表示点的编号。它不能做成属性列：`CREATE NODE TYPE Company (id INT64 NULL)` 会失败。节点定义为 `STRING(n)` 时，编号使用字符串字面量，例如 `id:'person-001'`。

## 属性类型

建类型时写出列名、类型，需要可空时再写 `NULL`。不写 `NULL` 的列必须有值，空着会报「属性 … 不能为空」。

| 写法 | 存成 | 说明 |
|---|---|---|
| `BOOL` 或 `BOOLEAN` | 布尔 | `true`、`false` |
| `INT`、`INTEGER`、`INT64` | 64 位整数 | 范围是 Java `long` |
| `DOUBLE` | 双精度浮点 | |
| `STRING` | 字符串 | 最长 64KiB |
| `DATETIME` | UTC 毫秒 | 返回时是 ISO 字符串 |

```text
CREATE NODE TYPE Company (name STRING, founded DATETIME NULL, active BOOL NULL)
```

字段可以附带注释：

```text
CREATE NODE TYPE Company COMMENT '企业节点' (
    name STRING COMMENT '企业名称',
    founded DATETIME NULL COMMENT '成立时间',
    active BOOL NULL COMMENT '是否有效'
)
```

`name` 必填。`founded` 和 `active` 可以不写。

时间字面量：

```text
DATETIME '2024-01-31T12:00:00Z'
DATETIME '2024-01-31 12:00:00'
```

第二种不带时区，按 UTC。插入和比较都用这种字面量。

## 表达式里的字面量

| 写法 | 含义 |
|---|---|
| `1`、`-2` | 整数 |
| `0.5` | 浮点 |
| `'root'` | 字符串，用单引号 |
| `true`、`false` | 布尔 |
| `NULL` | 空 |

字符串里没有转义说明以外的复杂字面量。没有列表字面量、映射字面量。`IN (1, 2, 3)` 是运算符，括号里是若干表达式，不是一个可以存进属性的列表。

## 参数

语句里写 `$名字`。值由客户端在 `params` 里传入，键是名字，不带 `$`。

```text
MATCH (a:Company {id: $id}) RETURN a.name
```

```json
{"op":"execute","session":"...","query":"MATCH (a:Company {id: $id}) RETURN a.name","params":{"id":1}}
```

交互客户端发出的 `params` 是空对象。在命令行里写 `$id` 会因为找不到参数失败，那里直接写字面量。

`//` 和 `/* ... */` 是解析阶段注释，不会保存；`COMMENT '...'` 是 Schema 元数据，会通过 `SHOW` / `DESCRIBE` 返回。

## 标准里还有

标准还有日期、不含日期的时间、时间段、列表、记录，以及这些类型的构造和函数。这里的属性列只有上面五种。

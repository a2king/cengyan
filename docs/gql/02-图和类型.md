# 图和类型

所有读写都落在当前图。先 `CREATE GRAPH`，再 `USE`。没 `USE` 就 `INSERT` 或 `MATCH`，会找不到当前图。

## 图和别名

```text
CREATE GRAPH Company COMMENT '企业关系图谱'
USE Company
CREATE ALIAS corp FOR GRAPH Company
SHOW GRAPHS
SHOW ALIASES
DROP ALIAS corp
DROP GRAPH Company
```

别名指向一张图，不能指向另一个别名。`USE corp` 和 `USE Company` 进入同一张图。`DROP GRAPH` 删这张图，同时删掉指向它的别名。只删别名、留下图，用 `DROP ALIAS`。`DROP GRAPH` 不能拿别名当图名。

`SHOW GRAPHS` 的列是 `name`、`comment`，别名不出现在这里。`SHOW ALIASES` 的列是 `alias`、`canonical`、`graphId`。`canonical` 是别名指向的图名。

## 点类型和边类型

类型建在当前图上。点类型、边类型的名字在这张图里各自不能重复。

```text
CREATE NODE TYPE Company ID INT (name STRING, capital INT64 NULL)
CREATE NODE TYPE Person COMMENT '人员节点' ID STRING(64) (name STRING NULL COMMENT '姓名')
CREATE REL TYPE holder COMMENT '持有关系' (ratio DOUBLE NULL COMMENT '比例')
SHOW NODE TYPES
SHOW REL TYPES
DESCRIBE NODE TYPE Company
DESCRIBE REL TYPE holder
```

`SHOW NODE TYPES` 的列是 `name`、`id`、`schemaVersion`、`idType`、`idLength`、`comment`；`SHOW REL TYPES` 的列是 `name`、`id`、`schemaVersion`、`comment`。`DESCRIBE` 的列是 `property`、`type`、`nullable`、`comment`。类型可以暂时没有属性：

```text
CREATE NODE TYPE Company ()
```

节点 ID 类型可以是 `INT` 或 `STRING(n)`。`INT` 是非负整数，默认最大 19 位；`STRING(n)` 按 UTF-8 字节数限制长度。省略 `ID` 时默认使用 `INT`。

建好以后只能在末尾加可空列，不能加必填列，不能删列，不能改列的类型：

```text
ALTER NODE TYPE Company ADD note STRING NULL
ALTER REL TYPE holder ADD since DATETIME NULL COMMENT '关系建立时间'
```

## 一个类型名

点模式里的类型写成 `:Company`，可以不写。边类型见 [插入](03-插入.md) 和 [查询](04-查询.md)。一个点在创建时只有这一个类型，以后也不能再给它加第二个类型名。

## 标准里还有

标准把「图的类型」和「图里的数据」分成两样东西：先有图类型，再建图。点可以同时有多个标签，边的端点类型可以写在图类型里。主键也写在类型定义里，不固定叫 `id`。

这里没有这层图类型。`CREATE NODE TYPE` 直接改当前图的目录。编号永远是 `id`。

## Schema 注释语法

图空间、点类型、边类型和字段都可以使用 `COMMENT` 保存说明。注释是目录元数据，不是 `//` 或 `/* ... */` 解析注释。

```text
CREATE GRAPH Company COMMENT '企业关系图谱'
CREATE NODE TYPE org COMMENT '企业节点' ID STRING(64) (entname STRING NULL COMMENT '企业名称')
CREATE REL TYPE inv COMMENT '投资关系' (conprop DOUBLE NULL COMMENT '持股比例')
```

`SHOW GRAPHS`、`SHOW NODE TYPES`、`SHOW REL TYPES` 和 `DESCRIBE` 会在结果中返回 `comment` 列。

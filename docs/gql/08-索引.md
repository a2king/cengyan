# 索引

索引是当前图上的目录对象。标准 GQL 规定的是图类型里的键，不规定这种二级索引。下面是层岩自己的写法。

## 建立、查看、删除

```text
CREATE INDEX by_name ON NODE TYPE Company (name)
CREATE UNIQUE INDEX by_ratio ON REL TYPE holder (ratio)
SHOW INDEXES
DROP INDEX by_name
```

`SHOW INDEXES` 的列是 `name`、`target`、`type`、`properties`、`unique`、`ready`。

`CREATE INDEX` 只登记目录。这时 `ready` 是 false，查询不会用它。已经存在的数据不会自动补进索引。写入新数据时仍会维护这个索引的键。

把已有数据补进索引，并把它标成可用，用运维命令，不是 GQL：

```text
:rebuildIndex by_name
```

完成后 `ready` 为 true。等值和数值范围才会走索引。

## 哪些条件会用索引

一跳、并且边上只写了一个类型时，才可能用边索引。多个类型、不写类型、变长跳，都不走边索引。

| 属性类型 | 等值 | 范围（`<` `<=` `>` `>=`） |
|---|---|---|
| `STRING` | 会 | 不会，改扫边或扫点 |
| `INT64`、`DOUBLE`、`DATETIME` | 会 | 会 |
| `BOOL` | 会 | 不会 |

`NULL` 不写进索引。多条 `NULL` 不算违反唯一索引。唯一索引冲突报 `UNIQUE_VIOLATION`。

索引还没 `ready` 时，同一条 `WHERE` 改走扫描。空的索引命中表示「用了索引，并且没有行」，不会再退回去全表扫。

## 和类型定义的差别

类型上的必填列不是索引。唯一性只来自 `CREATE UNIQUE INDEX`。点的 `id` 本身就是点的编号，不需要再为 `id` 建索引。

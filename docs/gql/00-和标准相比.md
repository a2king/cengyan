# 和标准 GQL 相比

对照的是 ISO/IEC 39075（GQL）。层岩现在能执行的是其中一小段，写法更接近「一个点、一条边、然后 RETURN」。一次只提交一条语句，末尾可以有一个分号，不能用分号把两条拼在一起。

## 已经有的

- 当前图：`CREATE GRAPH`、`USE`、别名、`SHOW`、`DESCRIBE`。
- 点只有一个类型名，边只有一个类型名。边上可以用 `|` 列出几个类型，也可以不写类型。
- 点的编号是 `id`，类型为 `INT64`。它写在模式里，不是普通属性列。
- 边有方向，同一对点用 `rank` 区分多条边。
- 查询模式是 `(起点)`，或者 `(起点)-[边]->(终点)`。变长跳写在箭头后面，必须有上界。
- `RETURN`、`DISTINCT`、`ORDER BY`、`SKIP`、`LIMIT`。
- `INSERT`、`SET`、`DELETE`。
- `count` 和 `sum`。
- 三个过程：`path.shortest`、`subgraph.bounded`、`ownership.largest_holder`。
- 属性索引是目录功能，标准查询语言本身不规定这种二级索引。

## 标准里有、这里还没有

按学习时最容易撞上的缺口排列。

**图和类型**

- 图类型和图数据分开。标准先定义图类型，再建符合这个类型的图。这里的类型直接建在当前图上。
- 一个点可以有多个标签。标签表达式还有「并且」「排除」。这里一个点、一条边都只有一个类型名，点上不能写 `|`。
- 主键写在类型定义里。这里的编号固定叫 `id`。
- 更多数据类型：单独的日期、时间、带时区的时间、时间段、列表、记录。这里只有 `BOOL`、`INT64`、`DOUBLE`、`STRING`、`DATETIME`。
- 改列名、删列、改类型、在中间插列。这里只能在末尾加可空列。

**查询模式**

- `OPTIONAL MATCH`：对不上时留空行，而不是整行丢掉。
- 一条 `MATCH` 里写多段路径、多个模式，或者给整条路径一个变量。
- 无上界变长：`*`、`+`。这里写 `*` 会直接报错。
- 路径语义：是否允许重复点、重复边。这里的变长是「点进过就不再进」。
- 写在语句里的最短路（`SHORTEST` 等）。这里最短路只能用 `CALL path.shortest`。
- 不指定起点、按一种关系从全图取出 `LIMIT 100` 条边。标准的 `MATCH` 可以这样扫。这里不写起点 `id` 时，先扫点，扫点上限是 `max_edges_per_vertex`（默认 64），点一多就以 `TRUNCATED` 失败，`LIMIT` 停不住这次扫点。

**把结果接起来**

- `WITH`、`NEXT`：前一段的结果变成后一段的输入。
- `UNION`、`EXCEPT`、`INTERSECT`。
- `FILTER`、`LET`。
- `OFFSET`。这里用 `SKIP`。
- 按某个键分组再聚合。这里的 `count`、`sum` 是整段结果一个数，不能和普通列写在一起。
- 先对全部匹配排序，再取前 N 行。一跳查询在写了 `LIMIT` 或 `SKIP` 时，先按扫描顺序收满这个窗口，再在这些行里排序。多跳是先扩完（仍受每跳点数上限约束），再排序和截断。

**表达式**

- `CASE`。
- 列表、映射字面量，以及字符串函数、日期函数。
- `avg`、`min`、`max`、`collect`。
- 子查询，例如 `EXISTS { MATCH ... }`。
- `type(e)` 这种调用。求值器认识 `type`，但 `type` 是关键字，解析阶段写不出来。边的类型看 `RETURN e` 结果里的 `type` 字段。`labels(a)` 可以写，返回的是这一个类型名，不是标签列表。

**修改**

- `MERGE`：有则匹配，无则插入。
- `REMOVE`：删掉某个属性。
- `DETACH DELETE`：删点时一并删掉相连的边。这里删点时，相连的边要自己再删。
- 一条语句插入多条边，或者插入一条没有类型、没有方向的边。
- `BEGIN`、`COMMIT`、`ROLLBACK`。一条修改语句自己提交，失败不留下半截结果；没有跨语句事务。

**过程**

标准有过程调用这一种语句形式。具体有哪些过程由实现提供。这里固定三个，参数和 `YIELD` 列都是写死的。

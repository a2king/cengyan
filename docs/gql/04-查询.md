# 查询

`MATCH` 读当前图。可以只写点，也可以把多段边连在同一条模式里，例如 `(a)-[:inv]->(b)-[:inv]->(c)`。逗号把多个模式连在一起，`OPTIONAL MATCH` 对不上时保留左行并把新变量留空。

## 只有点

```text
MATCH (a:Company {id:1}) RETURN a
MATCH (a:Company {id:1}) RETURN a.id, a.name
MATCH (p:org {id:100}) RETURN p
```

`{id:1}` 或 `{id:'person-001'}` 是点的编号，用来直接定位。类型名用来确认这个点是不是这个类型；对不上就没有行。

不写 `id` 时，按类型把点扫出来：

```text
MATCH (a:Company) RETURN a.id
```

扫描是否有上限由 `max_edges_per_vertex` 执行预算决定。默认值为 `0`（不限）；部署者配置正数后，超过预算会返回 `TRUNCATED`。`LIMIT` 只控制结果窗口。

既不写 `id` 也不写类型，会报「起点需要 id 或节点类型」。

## 一条边

```text
MATCH (a:Company {id:1})-[e:holder]->(b) RETURN b.id, e.ratio
MATCH (a:Company {id:1})<-[:holder]-(b) RETURN b.id
MATCH (a:Company {id:1})-[:holder]-(b) RETURN b.id
```

方向：

| 写法 | 含义 |
|---|---|
| `-[e:holder]->` | 从左边的点出发的出边 |
| `<-[e:holder]-` | 指向左边的点的入边 |
| `-[e:holder]-` | 两个方向。同一条边只出现一次 |

类型：

```text
MATCH (a {id:1})-[e:holder]->(b) RETURN e
MATCH (a {id:1})-[e:holder|:works]->(b) RETURN b.id
MATCH (a {id:1})-[e]->(b) RETURN e
```

- 一个类型：只匹配这个类型。
- `|`：匹配列出的类型。每个名字前面的冒号可以省略，`:holder|works` 和 `:holder|:works` 一样。重复的类型名会报「边类型重复」。
- 不写类型：这个方向上的任何关系。

`RETURN e` 时，结果里的 `type` 是这条边自己的类型。

不写类型，或者用 `|` 写了多个类型时，未选中的边也会计入扫描预算。配置了 `max_edges_per_vertex` 且超过时返回 `TRUNCATED`，不会少返回几行就算成功。

模式里可以写要相等的属性，用来过滤：

```text
MATCH (a:Company {id:1, name:'root'})-[e:holder {ratio:0.5}]->(b) RETURN b.id
```

终点也可以写编号：`(b {id:2})`。

## 从全图按关系取 100 条

下面这句在标准里表示「任意起点上的 `holder` 边，最多 100 条」：

```text
MATCH (a)-[e:holder]->(b) RETURN e LIMIT 100
```

这里执行不了：起点没有 `id` 也没有类型。写成 `(a:Company)-[e:holder]->(b)` 会先扫点，点的数量一超过每点上限就失败，`LIMIT 100` 不会改掉这次扫点。要从一个已知点取边，把 `id` 写上：

```text
MATCH (a:Company {id:1})-[e:holder]->(b) RETURN e LIMIT 100
```

`LIMIT` 只限制返回行数。这个点上检查的边仍然不能超过每点上限。

## WHERE、RETURN、排序和截断

```text
MATCH (a:Company {id:1})-[e:holder]->(b)
WHERE b.id <> 9 AND e.ratio >= 0.2
RETURN b.id AS id, e.ratio
ORDER BY id DESC
SKIP 0
LIMIT 10
```

`AS` 给这一列起名。不写 `AS` 时，列名是你写下的那一段文本。

`DISTINCT` 按整行去重：

```text
MATCH (a:Company {id:1})-[:holder]->(b) RETURN DISTINCT b.id
```

`ORDER BY` 后面可以写 `ASC` 或 `DESC`，不写是升序。排序的表达式可以是 `RETURN` 里的别名。

`SKIP` 丢掉前面若干行，`LIMIT` 保留若干行。

没有 `ORDER BY` 时，`LIMIT` 可以提前停住扫描。写了 `ORDER BY` 时先收集匹配再排序，然后才 `SKIP` / `LIMIT`，所以 `ORDER BY x DESC LIMIT 10` 是真正的前 10 名。`OFFSET` 和 `SKIP` 是同一个意思。

## 还要知道的差别

点上可以写 `:org|person`、`:!org`、`:%`。一个点在库里仍然只有一个类型，标签表达式只用来选择类型。无上界的 `*`、`+`、`{2,}` 可以写；`max_hops` 为 0（不限）时必须自己写出上界。路径模式可以写 `WALK`、`TRAIL`、`SIMPLE`、`ACYCLIC`，不写时变长跳仍按「每个点到达一次」执行，写了 `WALK` 才是每条路径一行。

## 执行计划查看

可以使用层岩扩展 `EXPLAIN` 查看当前查询的大致执行路径：

```text
EXPLAIN MATCH (a:Company {id:1}) RETURN a
```

返回的 `operator` / `detail` 行用于确认点 ID 查找、节点扫描、过滤、排序、窗口和投影。它是轻量诊断信息，不是完整代价优化器的计划。

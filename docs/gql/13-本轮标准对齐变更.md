# 本轮标准对齐变更

对照 ISO/IEC 39075:2024 做的一轮修正。目标：标准写法都能解析、含义和标准一致；层岩扩展保留。

## 不兼容变更（升级前看）

| 变更 | 以前 | 现在 | 要做什么 |
|---|---|---|---|
| 属性可空 | 不写 `NULL` 是必填 | 默认可空，写 `NOT NULL` 才必填 | 旧 DDL 里要必填的列补上 `NOT NULL`。已建好的类型不变。Studio 生成的 DDL 已改成显式写 `NULL` / `NOT NULL` |
| `--` | `a--b` 是 `a - (-b)` | 行注释 | 写成 `a - -b` 或 `a + b` |
| `OR` / `XOR` | `XOR` 比 `OR` 优先，且 `a XOR b AND c` 解析失败 | 同一级，从左到右 | 依赖旧优先级的条件加括号 |
| 标识符 | 只有 ASCII，中文要反引号 | Unicode 字母可以直接写 | 无 |
| `LIST` / `ARRAY` / `RECORD` / `VALUE` 等 | 可以当变量名 | 后面跟 `[` / `{` 时是构造器、子查询 | 叫 `list` 的变量后面不要直接接 `[` |
| `USE g 查询` | 报错 | 只对这一条查询换图，不切换当前图 | 无 |
| `-[:A\|B]->` | 实际不过滤类型，所有类型的边都会匹配 | 只匹配 A、B | 无（这是修正） |
| `SHORTEST k`（k > 1） | 只返回最短那一层 | 按长度返回前 k 条 | 无（这是修正） |
| 过程的单个映射参数 `CALL p($m)` | 取不到参数 | 按映射展开 | 无（这是修正） |

## 修正的问题

- `REMOVE n.prop` 解析不了（解析器只读变量名，执行器要的是 `n.prop`），整条链路不可用。
- `SAME()`、`ALL_DIFFERENT()`、`PROPERTY_EXISTS()` 有求值代码但解析器从不生成，运行时报「未知函数」。
- `EXISTS { }` 解析时要求写 `RETURN`，执行器也没有接上子查询，运行时报「这里还不能写子查询」。
- 量化路径模式 `((a)-[e]->(b)){m,n}` 能解析但执行器报「远程分组路径模式尚未接入」。
- `MATCH ... SET ... DELETE` 同时写时，旧的快速路径会丢掉 `SET`。
- `CALL 过程 YIELD x FILTER ...` 没有 `RETURN` 时 `FILTER` 被丢掉；现在要求写 `RETURN`。
- `a<-1` 被当成左箭头；现在是 `a < -1`。
- Studio 把 `USE g MATCH ...` 也当成切换当前图。
- 子查询（内联 `CALL`、`VALUE`）里写入会被权限检查当成只读；现在解析阶段就拒绝。

## 没有做（需要改存储或会话模型）

- 多标签、跨语句事务、新的属性类型（`DATE` / `TIME` / `DURATION` / `LIST` / `RECORD` / `BYTES` / `DECIMAL` / 定宽整数）。
- 图类型对象、`SESSION` 的其他命令、`KEEP`、`SELECT`、`NULLS FIRST/LAST`。
- 边类型端点约束的写入校验。

这些写法现在会给出明确的「不支持」报错。

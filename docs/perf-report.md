# 性能测试记录

## 口径说明

本表前面的记录主要是进程内 RocksDB/QueryEngine 基准，不包含 TCP、JSON、Netty 和客户端等待时间。同一场景会因 JVM、冷热缓存、系统负载和 RocksDB compaction 波动。不要把不同日期的单次 p99 当作 SLA。

最近一次端到端服务测试（本机 i5-14600K、JDK 21、热数据、`query_threads=16`）结果：

| 场景 | 吞吐/延迟 | 说明 |
|---|---:|---|
| 单连接逐条节点写入 | 约 2464 行/秒 | 旧逐条 GQL 路径 |
| 4 连接逐条节点写入 | 约 3109 行/秒 | 受全局写锁影响，非线性扩展 |
| `bulkInsert` 节点写入 | 约 121000 行/秒 | 10000 行，分成 1000 行批次，热数据；仅作方向性参考 |
| 16 路并发一跳查询 | 约 1382 QPS，p99 约 5.9 ms | 包含网络和 JSON |
| 32 路并发一跳查询 | 约 3160 QPS，p99 约 27.6 ms | 尾延迟开始明显上升 |

批量导入性能高度依赖属性大小、索引数量、磁盘、WAL、分区并发和 compaction。正式容量规划必须在目标机器和目标数据分布上复测。
